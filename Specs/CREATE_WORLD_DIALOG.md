# Create world dialog

When creating a new world, the user sees Worldhalla's own dialog in place of Valheim's new world dialog.
It reuses Valheim's UI elements wherever possible and has the following elements:

#### Column 1

- World name input
- World seed input, with a refresh seed button to its right
- Generator selection
- Generator description
- Settings summary, with a settings button
- Generator settings summary, with a generator settings button

#### Column 2

- World preview
- World preview hide button
- World preview details button
- Create button
- Cancel button

## Functionality per element:

### World name input, world seed input, Create and Cancel button

Name, seed, create and cancel are vanilla's own controls and keep vanilla's behavior: creating a world goes through
vanilla's validation and save, with the selected generator and its settings attached to the new world.

The seed input is shortened to make room for a square new seed button on its right, reusing the server list's
refresh button. Clicking it replaces the seed with a fresh one generated by vanilla's rules (`World.GenerateSeed`).

### Generator select

The generator select, labelled "Generator", offers Valheim and every registered generator. Each generator option shows
its name followed by its guid in gray, so the name stands out. The "Valheim" option is special
and if chosen, creates a vanilla, completely unmodded world.

### Generator description

Right below the generator select, a read-only text box two lines high shows the selected generator's
`IWorldGenerator.Description`, or a short note on vanilla generation for the "Valheim" option. Longer text scrolls
vertically, with the mouse wheel, by dragging, or with the right stick, as vanilla's changelog does. The box makes
column 1 taller, so the preview, which matches column 1's height, grows with it and the dialog widens to fit.

### Generator settings summary & generator settings button

Each settings summary has its label on the left and a small "Edit" button at the right end of the label's row, above
the summary's top right corner; the summary box sits underneath both.

The summary is a labeled text box where our selected worldgen will output ISettings.Summary
for the currently selected settings. The generator settings button opens a dialog showing the settings form the
generator provides through ISettingsHandler. If the currently selected generator doesn't support any settings
(is vanilla or doesn't implement ISettingsHandler) the button must be grayed out.

### Settings summary & settings button

Functionally equivalent to the above paragraph, but for global worldhalla world settings rather than
generator-specific. Since we currently have no global settings, we leave the textbox empty and
button similarly leading to nothing else but a log. If selected worldgen is vanilla, settings
button must be grayed out.

### World preview and its buttons

World preview is a medium-sized circle window that shows a very basic preview of
how the selected world is going to look. A thin gold ring outlines it; while it is hovered or selected with a controller, a wider,
brighter ring shows over it. When entering the creation dialog this circle should be blank
with a label of "click to reveal". If it's clicked, a YES/NO dialog should show warning the user about
spoilers, if the user clicks the yes button, world preview will start loading. The procedure will be explained below.

The values that affect generation are the seed, the generator and (once they exist) the settings; the world name
doesn't. If one of them changes while the preview is revealed, the preview is no longer accurate: it is cleared and
regenerates automatically, without another click. A click is only required for the first reveal and after Hide.
The hide button is only enabled if we have already revealed the map and clicking
it resets the preview window to its initial state. If clicked again it will no longer show the YES/NO dialog
as the user has already stated their intent. This behavior only persists through one world creation dialog session.

Column 2 ends level with column 1: Create and Cancel sit at the bottom edge of the layout, and the preview circle
grows to take all the height the buttons below it leave free. Its bitmap is rendered at its displayed size.

Hide and details are small buttons in the lower left and lower right corners of the square enclosing the circle,
in the space the circle leaves free. Both are icon buttons the size of the new seed button, built from the same
server list refresh button: details shows a magnifying glass, hide a crossed-out eye. The icons are drawn at runtime,
not shipped, in the style of the game's refresh icon (20 px, solid white, strokes about 2.5–3 px).

#### World preview procedure

Instantiate IWorldState with the current settings on a background thread and query the result into a bitmap.
The asynchronous task for this is owned by the creation dialog, it should be completely gone if the dialog is closed.
The generation process is currently uninterruptible, so on regeneration we wait for the finish of the last one,
discard the result and start anew. Point sampling is interruptible, so on regeneration (or hide) we just stop
immediately and throw away whatever's been generated yet.

Seed edits are debounced: regeneration starts 0.5 s after the last keystroke. At most one generation runs at a time;
requests arriving meanwhile don't queue up, only the latest one is kept and started once the running one finishes.
An empty seed is a valid seed (vanilla stores it as seed 0) and is previewed like any other.

While IWorldState is being created the circle shows a spinner. Sampling then fills the bitmap top to bottom,
so progress is visible as it goes.

The preview covers the world disc: radius `IWorldGeography.WorldSize / 2` when the world state implements it,
otherwise 10500 m.

Vanilla has no IWorldState. The preview samples a private vanilla `WorldGenerator` instance instead. Its constructor
seeds through the engine's global `UnityEngine.Random`, so it runs on the main thread, as a menu world so that it skips
river placement. River placement then runs on the preview thread through private copies of vanilla's placement
methods (Harmony reverse patches), rewritten to draw from a reimplementation of the engine's generator (xorshift128)
instead of `UnityEngine.Random`. These copies are for the preview only: the original `WorldGenerator` methods must
never be patched by this, since they place the rivers of every vanilla world that is actually played.

The reimplementation reproduces the engine bit for bit; this was verified in game once, not at every start. If the
copies can't be made, the vanilla preview is shown without rivers. If the vanilla preview can't be made at all, the
circle says "Preview failed".

#### World preview style

The two previews are painted differently, since what reads well at 300 px is not what reads well at 1024 px.

The small preview is about biome distribution only: one flat color per biome, no height tint and no shading.
Anything below sea level is water, whatever its biome, with one exception: swamp less than 2 m under water keeps
the swamp color, since shallow flooded ground is what a swamp is made of.
Each pixel averages 3 × 3 samples: one sample per pixel is about 70 m apart, which misses or randomly hits narrow
straits and lakes, drawing land bridges that don't exist and making broken terrain such as the Mistlands look more
solid than it is.
Water has a shallow and a deep tone, but they are kept very close so they don't compete with the biome colors.
Land and sea must be told apart at a glance: water is a dark navy, clearly darker than every biome color, so
even the darkest biomes (Black Forest, Mistlands) don't blend into it.

The details preview is a detailed map: biome colors ranging with height, water shaded by depth, hillshading from the
height derivative, a coastline stroke and height isolines (20 m, 40 m, then every 40 m from 60 m). The strokes are
drawn per pixel, where a pixel's height band differs from its neighbour's, rather than traced as marching-squares
segments.

The details preview also carries a world grid in thin (about 1 px) lines, blended halfway towards beige: the world
centre, a ring every 1000 m, the two axes and the two diagonals.

#### World preview details

A new closable dialog that displays the same world with a larger size and resolution. Should share IWorldState (and its
creation process) with the parent dialog to avoid recomputation. Grayed out if world preview isn't yet enabled.
It samples when opened and keeps its bitmap until the preview is invalidated.

#### Sizes

| | Bitmap resolution |
|---|---|
| Preview circle | fills column 2 (about 390 × 390) |
| Details dialog | 1024 × 1024 |

The details dialog is kept tight around its map (about 12 px of padding) and is scaled down as a whole when it
doesn't fit the screen, so lower game resolutions show it smaller rather than cropped.
